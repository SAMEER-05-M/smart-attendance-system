## 1. Project Overview & Problem Statement

### Context & Problem Statement
Traditional paper-based attendance registers and legacy biometric hardware scanners in academic institutions suffer from significant vulnerabilities:
1. **Time Inefficiency:** Taking roll calls in classrooms with 60+ students consumes 10–15% of instructional lecture time.
2. **Proxy Attendance Vulnerabilities:** Manual signing allows students to sign on behalf of absent peers ("buddy punching").
3. **Hardware Fragility & Bottlenecks:** Physical fingerprint readers lead to long queues at classroom doorways and suffer from optical sensor degradation.
4. **Delayed Intervention:** Attendance shortages (falling below the mandatory 75% university threshold) are frequently calculated only at the end of the semester, preventing timely academic remedial action.

### Project Objectives
**Smart Attendance Management System (SAMS)** is an enterprise-grade academic web application engineered with:
- **Time-Limited Cryptographic Dynamic QR Codes:** Generated by faculty on an interactive live board with automatic server expiration.
- **Biometric Face Verification Engine:** 128-dimensional facial feature descriptor extraction and L2 Euclidean distance matching with explicit consent safeguards.
- **Strict Server-Side Validation:** Dual checks ensuring students belong to the active class section, non-expired tokens, and automated duplicate prevention.
- **Real-Time Analytics & Shortage Tracking:** Live student attendance calculation from database session records, warning indicators, and formal grievance correction workflows.

## 2. Technology Stack

### Frontend
- **Framework:** React 18 with TypeScript
- **Build Tool:** Vite 6
- **Styling:** Vanilla Tailwind CSS with custom Deep Red (`#881337`), White, and Charcoal Black palette
- **Icons:** Lucide React
- **Analytics & Charts:** Recharts (Area charts for weekly trends, Bar charts for subject analytics)
- **Routing:** React Router v6 with Role-Based Protected Routes
- **QR Code Scanning & Generation:** `html5-qrcode` & `qrcode.react`

### Backend
- **Runtime:** Node.js (v20+) with TypeScript
- **Web Framework:** Express.js (REST API architecture)
- **Authentication:** JWT (JSON Web Tokens) with 24-hour expiration & role claims
- **Password Hashing:** `bcryptjs` (salt factor 10)
- **Validation:** Zod schemas for all request payloads
- **ORM:** Prisma ORM v5
- **Testing:** Vitest & Supertest automated suite

### Database
- **Engine:** PostgreSQL compatible Prisma Schema (configured with SQLite `file:./dev.db` for instant, zero-dependency local evaluation; seamlessly switchable to PostgreSQL via `.env`).

### Roles Enforced by Server RBAC:
1. **ADMIN:** Access college-wide statistics, manage students/faculty/academics, adjust shortage threshold (default 75%), review student grievance requests, inspect security audit logs.
2. **FACULTY:** View assigned subjects, initiate live attendance sessions with configurable countdown timers, display dynamic QR codes, monitor live student roster updates in real-time, manually correct attendance with mandatory audit reasons.
3. **STUDENT:** View personalized attendance percentage (color-coded: Green $\ge 75\%$, Amber $70\text{--}74\%$, Red $<70\%$), scan classroom QR codes with camera, enroll 128D facial biometrics, inspect class history, and submit formal attendance correction requests.

## 4. Database Schema Design (Prisma)

The database schema enforces referential integrity, cascading deletes where appropriate, and unique compound constraints to prevent duplicate entries:

| Model | Purpose | Critical Constraints & Keys |
|---|---|---|
| `User` | Base login credentials and profile metadata | Unique `email`, indexed `role` (`ADMIN`, `FACULTY`, `STUDENT`) |
| `StudentProfile` | Institutional roll number and semester info | Unique `rollNumber`, 1-to-1 with `User` |
| `FacultyProfile` | Staff employee ID and designation | Unique `employeeId`, 1-to-1 with `User` |
| `Department` | Academic department (e.g. CSE) | Unique `code` |
| `Course` | Degree program (e.g. B.Tech in CSE AI/ML) | Unique `code`, linked to `Department` |
| `Subject` | Academic subject (e.g. AI601 Deep Learning) | Unique `code`, linked to `Department` |
| `ClassSection` | Student cohort (e.g. Section A, AY 2026-27) | Compound unique on `[name, academicYear, semester, courseId]` |
| `Enrollment` | Maps students to class sections | Compound unique on `[studentProfileId, classSectionId]` |
| `FacultyAssignment` | Assigns faculty to teach a subject in a section | Compound unique on `[facultyProfileId, subjectId, classSectionId, academicYear]` |
| `AttendanceSession` | Classroom attendance lecture instance | Unique `code`, unique `qrToken`, `qrTokenExpiresAt`, `status` |
| `AttendanceRecord` | Verified student attendance instance | **Compound unique `[attendanceSessionId, studentProfileId]`** (guarantees zero duplicate attendance entries!) |
| `AttendanceCorrectionRequest` | Student grievance ticket | Linked to student & session, status `PENDING`, `APPROVED`, `REJECTED` |
| `Notification` | Database-backed student and faculty alerts | Linked to `User`, tracks `isRead` |
| `AuditLog` | Cryptographic trail of logins & mutations | Captures `userId`, `action`, `entity`, `details`, and `ipAddress` |
| `FaceTemplate` | 128-D facial feature embeddings | 1-to-1 with `StudentProfile`, stores vector and explicit consent |
| `SystemSetting` | Configurable system hyperparameters | Key-value store (e.g. `attendance_threshold_percent: 75`) |

## 6. Installation & Quick Start Guide (Windows / VS Code)

### Prerequisites
- **Node.js** (v20 or v24 installed)
- **Git** (optional)
- VS Code or your preferred IDE

### Step 1: Open the Project
Open terminal in the project root directory:
```powershell
cd "c:\Users\vicky\OneDrive\Desktop\Smart Anttendance"
```

### Step 2: Install Dependencies
Install root, server, and client packages:
```powershell
npm run install:all
```
*(Or navigate to `server` and run `npm install`, then `client` and run `npm install`)*

### Step 3: Initialize Database & Seed Demo Data
The system is configured with SQLite by default for instant out-of-the-box local running without requiring a separate PostgreSQL server setup:
```powershell
cd server
npm run prisma:migrate
npm run prisma:seed
cd ..
```
This generates the Prisma client, creates the database tables, and seeds the 1 Admin, 2 Faculty, 10 Students, subjects, enrollments, and an active class session.

### Step 4: Run the Full-Stack Application
Start both the Express backend API and Vite React frontend concurrently with a single command:
```powershell
npm run dev
```

- **Frontend Client:** [http://localhost:5173](http://localhost:5173)
- **Backend API:** [http://localhost:5000](http://localhost:5000)
- **Health Check:** [http://localhost:5000/api/health](http://localhost:5000/api/health)

## 7. PostgreSQL Configuration (Optional Production Setup)

If college faculty or evaluators request PostgreSQL integration:
1. Ensure PostgreSQL is installed and running on your system (e.g., port 5432).
2. Open `server/.env` and uncomment the PostgreSQL connection string:
   ```env
   DATABASE_URL="postgresql://postgres:your_password@localhost:5432/sams_db?schema=public"
   ```
3. Copy the PostgreSQL Prisma schema:
   ```powershell
   cd server
   cp prisma/schema.postgresql.prisma prisma/schema.prisma
   npx prisma db push
   npm run prisma:seed
   ```
Because our schema models use portable, standard types with application-level validation, switching between PostgreSQL and SQLite is seamless.

## 8. REST API Reference

### Authentication
- `POST /api/auth/login` - Authenticate user & issue signed JWT.
- `GET /api/auth/me` - Fetch authenticated user profile & active enrollment.
- `POST /api/auth/logout` - Clear session & log audit event.

### Student Portal
- `GET /api/students/me` - Student profile and class section info.
- `GET /api/students/me/attendance` - Complete historical attendance records.
- `GET /api/students/me/attendance-summary` - Real-time calculation of overall & subject attendance percentages.
- `POST /api/students/me/correction-requests` - Submit grievance for missed class.
- `GET /api/students/me/correction-requests` - Check status of submitted requests.

### Attendance & QR Code
- `POST /api/attendance/qr/verify` - Student submits scanned QR token. Validates session status, expiry time, class enrollment, and blocks duplicate attempts.
- `POST /api/attendance/manual-mark` - Faculty manually logs attendance status with remarks.
- `PATCH /api/attendance/:id` - Faculty corrects an existing record with mandatory reason.

### Sessions (Faculty)
- `GET /api/faculty/me/subjects` - List assigned subjects and class sections.
- `GET /api/faculty/me/sessions` - List faculty's past and active sessions.
- `POST /api/sessions` - Create lecture session and generate unique time-limited QR token.
- `GET /api/sessions/:id` - Retrieve live session details and real-time student roster.
- `POST /api/sessions/:id/close` - Conclude session and mark remaining students ABSENT.

### AI/ML Face Recognition
- `POST /api/face/enroll` - Enroll 128-dimensional normalized facial embedding vector with explicit consent.
- `POST /api/face/verify` - Verify probe face against enrolled template using L2 Euclidean distance matching.

### Administration & Reports
- `GET /api/admin/stats` - Institutional metrics, today's attendance rate, weekly trends, shortage counts.
- `GET /api/admin/users` - List users filtered by role.
- `POST /api/admin/users` - Create student or faculty accounts.
- `PATCH /api/admin/users/:id/status` - Deactivate or activate account.
- `GET /api/admin/correction-requests` - List all college correction requests.
- `PATCH /api/admin/correction-requests/:id` - Approve or reject correction request (automatically updates the database attendance record!).
- `GET /api/admin/audit-logs` - Query security and action audit logs.
- `GET /api/admin/settings` & `POST /api/admin/settings` - Configure threshold %, grace period, QR expiry.
- `GET /api/reports/attendance` - Query filtered attendance records.
- `GET /api/reports/attendance/export` - Download real database attendance data as CSV.
- `GET /api/reports/shortage` - List students failing to meet mandatory threshold.

7. **QR Attendance Marking:** Enrolled student with valid token receives 200 and PRESENT status.
8. **Duplicate Attendance Prevention:** Submitting attendance twice for the same session is blocked with 409 Conflict.
9. **Class Membership Validation:** Students scanning QR for a section they are not enrolled in receive 403 Forbidden.
10. **Token Expiration Handling:** Expired QR codes are rejected with 400 Bad Request.
11. **Attendance Calculation:** Percentages are computed from database records without division by zero.
12. **Unauthorized Correction:** Students cannot directly edit attendance records (403 Forbidden).
13. **Faculty Correction:** Authorized faculty can correct records with a mandatory audit reason.

## 10. AI/ML Module Technical Details & Constraints

- **Biometric Privacy Safeguard:** Raw face images are **never stored** on the server or database.
- **Feature Vector Representation:** Only mathematical 128-dimensional floating-point embedding vectors are extracted and stored.
- **Distance Metric:** Compares probe vector $v_{\text{live}}$ against enrolled anchor $v_{\text{anchor}}$ using L2 Euclidean distance:
  $$d(v_1, v_2) = \sqrt{\sum_{i=1}^{128} (v_{1,i} - v_{2,i})^2}$$
- **Hyperparameter:** Threshold distance is configurable in Admin Settings (default $\le 0.60$ for match).
- **Known Browser Constraints:** Browser-based face processing is sensitive to ambient lighting, backlighting, webcam lens distortion, and yaw/pitch rotation. For academic rigor, the system provides camera QR scanning and faculty manual override as primary authoritative mechanisms.
